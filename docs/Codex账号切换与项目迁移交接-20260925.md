## 3. 切换 Codex 账号时怎么保留项目

### 仍在这台电脑、仍用这个目录

通常无需克隆或复制仓库。切换 Codex 登录账号后，在新账号的 Codex 中打开现有目录：

```text
C:\Users\hp-pc\Desktop\课题四\项目\UAV_USV_Platform
```

然后先检查：

```powershell
Set-Location 'C:\Users\hp-pc\Desktop\课题四\项目\UAV_USV_Platform'
git status --short --branch
git log -1 --oneline
git remote -v
```

新 Codex 账号不会自动获得旧聊天记录。把本文作为新会话的项目上下文，并明确说明“先保留当前工作区，不要清理或切分支”。Git 提交和本地文件属于电脑上的仓库；GitHub 登录凭据则由系统 Git 凭据管理器/浏览器账号维护，两者与 Codex 登录账号相互独立。

### 迁移到另一台电脑或新目录

必须同时考虑三类数据：

- **Git 提交历史**：可使用 Git bundle 或从确认过的 GitHub 地址重新克隆。
- **tracked 未提交修改**：普通克隆和 `git bundle` 都不会携带；需另存完整 diff/补丁。
- **untracked 文件及私有本地数据**：补丁通常也不会包含；需单独复制或打包，并逐项确认是否含密钥、录音或模型文件。

迁移前可以在旧电脑做只读清点：

```powershell
git status --short --branch
git diff --stat
git ls-files --others --exclude-standard
```

若选择补丁/打包迁移，应把它们存到仓库目录以外的安全位置；传输后在新电脑先核对文件清单、分支和 diff，再恢复到目标工作区。不要把 `.env`、访问令牌、内部服务凭据、真实录音、模型权重或数据库备份放到公开仓库或普通交接文本中。Git bundle 只能保留提交历史，不能作为完整工作区备份。
