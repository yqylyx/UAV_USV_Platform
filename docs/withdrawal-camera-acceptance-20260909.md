# 正向撤离与完整取景：修改及验收

日期：2026-09-09。仅部署本机，未提交或推送。保留其他本地修改。

## 已定位的原因

1. 原撤离控制先改变位置，再缓慢改变船头。护航目标和内层艇复用了位置追随逻辑，速度方向与船头没有正向约束，出现倒滑/侧滑。内层艇还可能为追逐身后的新槽位再次转头。
2. 仅把倒航分给守卫艇还不够：原来的 6 米撤离上限会让目标在守卫组真正倒航前停下，两个动作并不重叠。
3. 原镜头用分位数剔除离群设备、限制最远取景距离，且未完整考虑模型边缘、飞行高度及透视深度，无法保证全部设备入镜。
4. 截图与 Unity 取景回执不一致的直接原因是画布/视口尺寸竞争：展开后 CSS 和 GL viewport 为 1898×891，而 drawingBuffer 仍为 1177×751。测试捕获到 Unity `_emscripten_set_canvas_element_size` 在新尺寸生效后异步写回旧尺寸。仅在 resize 事件补一次宽高不能可靠解决。

## 实现

- 明确区分守卫组与正向撤离组。守卫艇继续朝敌倒航；护航目标及内层 USV 限速转向，朝向对准后沿船头正向加速。撤离期间不追逐后方槽位，不使用负的前进速度。
- 敌情确认后守卫部署与撤离转向并行启动。保留内层艇原相对位置，撤离路线允许有限横向修正，避免跨越护航目标换位。
- 撤离持续覆盖守卫动作；18 米为当前已检查的局部撤离空间上限，不是成功时间限制。交接仍要求真实撤离距离、所有方向朝敌倒航证据及安全距离，不能靠时间强制通过。
- 无共同安全方向时继续居中防御，不把整队强推向某一个敌船方向。
- 独立仿真相机按所有活动模型的完整包围盒计算取景，包含高度和透视深度，移除分位数剔除和固定最大距离；中心平滑移动，拉近有阻尼，扩展优先保证可见性。缓存 Renderer 引用，不每帧查找组件。
- 独立仿真 HTML 同步 CSS、画布 backing buffer 与 Unity 像素比；布局变化合并处理，监听宽高属性以修复延迟旧尺寸回写。稳定尺寸下不重复分配，不重建 iframe 或 Unity 实例。高分辨率渲染上限为约 1920×1080，以限制 GPU 开销。
- 回执增加低频完整取景指标；它只证明投影范围，不单独作为截图或流畅度合格证据。
- 30+30 主线程分析发现模型材质参数提交是主要热点；降分辨率和模型内同材质零件合批均做了对照测试，未改善慢帧比例。两个实验均未保留在交付代码中，不以新增代码量代替有效优化。

## 验收边界

- 较早 `final-3`、`final-10` 被诊断看门狗结束的运行不是完整通过；`buffer-fixed` 等目录为竞态修复前的失败证据。

- 不承诺任何硬件、任意超出本轮的规模都绝对无失帧。Mac 尺寸模拟不等于在真实 Mac/Safari 上测试。

## 大数量与布局复核

合批前完整 30+30 运行到序列 2455，4/4 目标完成；四个来袭方向各有两艘守卫 USV 连续倒航 4 秒，倒航距离 3.38–3.43 米。245 次完整取景采样均无越界。见 `large-final`。

合批前独立仿真帧间隔 P95 为 63.4 ms，超过 50 ms 的样本占约 15.4%，因此不能称为流畅度全部通过。降低分辨率的诊断运行 P95 仍为 62.8 ms，没有将该降画质方案部署。

生产分辨率布局复核覆盖 1366×768、1440×900、1920×1080、2560×1440、3840×2160，以及侧栏折叠/展开、页面往返和滚轮缩放。`cpu-final/30-layout.json` 的 13 个检查均保持同一实例，画布 backing buffer 与 GL viewport 一致。真实 Mac/Safari 未测。

30+30 后期多组分散时，最小模型包围盒投影长边约 9 px。全部入镜已解决，但“所有设备始终足够大、船头清楚”尚未达到。固定屏幕同时完整容纳分散实体时存在尺度限制；屏幕方向标记或分组近景属于展示方案选择，未经用户确认未加入。

合批实验版再次完整 30+30：序列 2455 完成，无页面异常、提示数量上限 1，四方向守卫均完成；P95 68.9 ms，超过 50 ms 为 1953/12663，未见有效改善，因此撤销该实验并重建。`batched-final` 仅作为实验记录，不代表交付版本。该轮 13 个布局检查额外使用 iframe 内存随机标记确认实例未重建，全部通过。

验收结论：正向撤离与守卫并行动作、全模型取景和画布尺寸竞态已修复并有证据；大规模慢帧及后期远处分组辨识度仍未通过。后续应继续区分动画/渲染提交及浏览器调度开销，并由用户确定最小方向标记或分组近景方案，不能继续无依据降低分辨率或添加算法补丁。
