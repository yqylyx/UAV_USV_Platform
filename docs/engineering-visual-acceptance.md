# 算法仿真：工程化画面验收规范

适用于本次及后续算法、Unity/WebGL、镜头和页面交互修改。用户要求：截图验收必须判断实际流程和逻辑，不能只确认页面能打开或状态显示成功。

## 验收原则

1. 先写预期动作与失败条件，再运行；不能看到结果后降低阈值。
2. 同时检查实际输出坐标、速度、船头方向、角色、事件序列和 WebGL 画面。算法自报的完成度不能代替独立判断。
3. 单张截图只能证明该时刻的布局。倒退、追击、加减速、抖动必须通过连续截图/录像及同序列轨迹证明。
4. 提示必须由已发生的动作触发，并对应正确目标；不能提前宣告“已出动”“已安全撤出”。多目标事件合并或排队，同屏只显示一条。
5. 功能、视觉、性能分开下结论。脚本完成、无控制台异常、无黑屏均不等同于流畅或视觉验收通过。
6. 失败场景保留配置、内部可复现种子、关键帧和失败原因，修复后重跑原配置及相关配置。测试观察窗口结束算未完成，不能强制算法成功。

## 必须核验的动作链

| 阶段 | 画面和数据共同满足的条件 | 直接判失败的情况 |
| --- | --- | --- |
| 生成/开始 | 护航目标位于编队保护范围内；开始后位置连续 | 开始时瞬移、目标跳到队外、模型嵌入地形 |
| 编队护航 | 编队有稳定分工，实际沿航线移动 | 无目的绕圈、角色频繁交换、无人保护目标 |
| 攻击意图 | 有相对接近和攻击方向证据，再出现对应提示 | 开始即随机宣布攻击、重复弹窗抢占画面 |
| 掩护撤离 | 前方屏障位于敌船和护航目标之间；护航目标撤离，守卫艇船头朝敌、缓慢倒退 | 船头随倒退速度转向背敌、只有文字没有动作 |
| 安全交接 | 连续观察到掩护动作，并确认安全距离，才转前出拦截 | 只按计时器结束守卫；危险时为演示而等待 |
| 紧急拦截 | 实际接近风险触发，单独记录紧急原因 | 未达到安全距离却显示“已安全撤出” |
| 追击/围捕 | 实际缩短可达路径、合理加减速；相邻设备不碰撞、不穿越 | 停在远处等待、贴边挤堆、无效摇头 |
| 完成 | 每艘敌船独立形成稳定环；全部参与围捕的无人艇船头朝敌 | 仅靠 UAV 补角掩盖 USV 缺口；完成后圈散开 |

2026-09-09 分向守卫判据：每个攻击方向的两艘守卫 USV 都连续 4 秒船头误差不超过 10°、朝敌反方向的实际速度至少 0.4 m/s、累计倒退至少 2.5 米；所有方向完成后才允许交接。4 秒是动作证据要求，不是强制交接期限。交接当前另检查所有未解除威胁距离护航目标至少 52 米；这只是现有距离门槛，不宣称已具备完整碰撞时间预测证明。

存在共同安全方向时采用掩护撤离；四面受敌且无共同安全方向时采用居中分层防御，不能再以“护航目标必须平移 4 米”验收该分支，也不能显示“已安全撤出”。3+3 在守卫阶段两艘 USV 前出、一艘内层保护，后续三艘均参与围捕。常规配置走紧急跳过路径必须判失败，不能用紧急例外抵消正常流程缺失。截图须覆盖每个方向，不能只选其中一艘敌船。

## 配置与界面回归

- 3+3、4+5、5+4、5+5、6+8、8+6、8+8、10+10、10+12、12+10、12+15、15+12、15+15、18+20、20+18、20+20、20+25、25+20、25+25、30+30。
- 围捕与护航分别测试；风险相关配置增加不同内部种子。种子用于自动化复现，不要求重新放回用户界面。
- 页面切换返回、左右折叠、放大/退出、滚轮缩放、暂停继续、重置重新生成应单独回归。
- 关键界面尺寸至少覆盖 1366×768、1440×900、1920×1080 和 2560×1440；自动化尺寸模拟不等于真实 Mac 硬件测试。
- 全局镜头既要完整包含任务对象，也要能辨认船头和编队；设备缩成点即记视觉缺陷。

## 性能取证

- 记录测试机器、GPU、浏览器、视口、Canvas 尺寸、同时运行的其他测试。
- 浏览器 requestAnimationFrame 间隔仅是渲染回调指标，不能直接称为 Unity GPU 帧率；必要时使用 Unity/浏览器性能剖析。
- 记录 P50/P95/P99 帧间隔、长帧、WebGL contextlost、帧数据到达节奏和仿真时间/实际时间比。
- 性能专项测试应单独运行，避免批量算法测试争抢 CPU 后误判产品瓶颈。
- 本轮未覆盖的维度必须写“未测/待确认”，不能写“全部通过”。
