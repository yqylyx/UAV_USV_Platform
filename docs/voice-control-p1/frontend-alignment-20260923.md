# P1 前端契约 v1.1 对齐回执

基线：合入 origin/mxy/p1-backend-20260923 的 09863cd，包含 mxy/p0-test-20260923 的 98fbe78 及后续 42ed66a。P0 的 96 条通过是后端隔离环境验收结论，本次仅运行前端回归与 P1 契约校验。

## 前端确认

- 接受后端 v1.1 字段、错误码、20/12 秒前端超时及 60 秒录音上限。durationMs 必须是 1–60000 整数。
- 超过 200 Unicode 码点的识别文本完整展示，提示编辑后再解析，不截断；请求文字保留原文供服务端计算摘要。
- 超时、取消或响应丢失时保留内存中的原请求体、音频 Blob 与 requestId；由用户点击“使用原请求恢复查询”重发相同 POST，不自动换键。
- VOICE_REQUEST_IN_PROGRESS / 429 遵循 Retry-After 冷却时间；VOICE_REQUEST_OUTCOME_UNKNOWN、VOICE_REQUEST_EXPIRED、IDEMPOTENCY_CONFLICT 等提供明确提示，不自动重新调用。
- 创建 P0 提案携带 X-Voice-Interpretation-ID；该来源 ID 在发送前写入现有 P0 恢复日志，重放时保持不变。手动四动作不加此头。
- 用户/角色、运行代次或 contextVersion 变化清除候选、停止录音并取消等待；服务器返回 401/403 后禁用新输入。实际撤权仍由后端逐次核验，前端不能凭本地角色保证权限。
- provider=test-fixture 明确显示“后端测试适配器”。本地解析 Mock 仅允许接 P0 Mock；其随机 requestId 不是后端解析记录，禁止用于真实提案。

## 联调设置

后端实现并启用测试适配器后，前端使用 VITE_VOICE_P1_PREPARATION=true、VITE_VOICE_P1_MOCK=false、VITE_VOICE_P1_BACKEND=true。P0 与 Unity 展示桥另按验收配置启用。当前保持本地配置，不替后端启用未实现接口。

## 需要共同明确的恢复边界

为遵守音频不持久化，P1 原请求恢复仅在当前输入组件会话内提供；卸载、刷新或用户切换后丢弃音频及文字，且不自动重发。P0 提案来源 ID 已持久保存并支持既有刷新恢复。若验收要求 P1 音频在刷新后仍可恢复，需后端补充仅凭请求 ID 查询的受权接口；当前契约只支持重发相同 POST，浏览器无法在不保存音频的情况下完成该操作。
