## 1. 本轮目标与边界

D2 把已经确认过的转写文字解析为候选意图。第一轮支持整队 `START`、`PAUSE`、`RESUME`、`STOP`，并识别否定表达、多动作歧义、不支持能力和单设备目标。解析结果不会直接执行，不会调用算法 Runner 或 Unity；候选仍必须进入 P0 冻结提案和人工确认。

第一轮采用 Java 内本地受限规则解析器 `local-rules/rules-v1`，用于先完成真实 HTTP、安全、幂等和 P0 来源关联。该结果不能表述为“真实 LLM 已接入”。后续接入本地 LLM 时复用同一公共契约，并增加结构化输出校验、模型超时和资源限流测试。

## 2. 公共接口

`POST /api/voice/intelligence/interpretations`

请求必须为 `application/json`，同时携带动态 CSRF，以及值相同的小写 UUID：`X-Request-ID`、`Idempotency-Key` 和正文 `requestId`。

```json
{
  "requestId": "11111111-1111-4111-8111-111111111111",
  "text": "暂停当前任务",
  "locale": "zh-CN",
  "allowedActions": ["START", "PAUSE", "RESUME", "STOP"],
  "availableDeviceCodes": ["UAV-001", "USV-001"],
  "runtimeContext": null
}
```

`text` 为 1–200 个 Unicode 码点且不能全为空白；数组不得重复，设备编号仅允许 `[A-Za-z0-9_.:-]`。未知字段、重复请求标识、查询参数及关联 ID 不一致均拒绝。

`runtimeContext=null` 允许独立解析；非空时必须包含 `runtimeRef`、`runtimeGeneration` 和 `contextVersion`。后端以数据库中的当前上下文为准，代次或版本不一致返回 `409 VOICE_CONTEXT_CHANGED`。

## 3. 结果分类

| status | 含义 | 是否可生成提案 |
|---|---|---|
| `CANDIDATE` | 唯一且受支持的整队动作 | 是 |
| `NEEDS_CLARIFICATION` | 无动作或一句多动作 | 否 |
| `UNSUPPORTED` | 不支持能力或单设备目标 | 否 |
| `NOT_ACTIONABLE` | 否定表达 | 否 |

候选示例：

```json
{
  "status": "CANDIDATE",
  "requestId": "11111111-1111-4111-8111-111111111111",
  "intent": "MISSION_PAUSE",
  "action": "PAUSE",
  "normalizedText": "暂停当前任务",
  "confidence": null,
  "provider": "local-rules",
  "model": "rules-v1"
}
```

规则解析没有概率输出，因此 `confidence=null`，不能伪造置信度。错误使用统一 `{code,message,data,timestamp}` 包装；权限、CSRF、幂等冲突、上下文变化和限流沿用既有错误码。

## 4. 幂等与来源关联

解析结果按 `userId + requestId` 去重，完整请求 JSON 的规范化哈希参与冲突检查。相同键、相同内容返回原结果；相同键、不同内容返回 `409 IDEMPOTENCY_CONFLICT`。内存最多 1000 条，终态保留 30 分钟，Java 重启后候选失效并安全拒绝来源关联。

前端用候选创建 P0 提案时必须传 `X-Voice-Interpretation-ID`。后端验证来源属于当前用户、状态为 `CANDIDATE`、动作与 P0 `intent` 一致，并核对非空运行上下文的 ref、generation 和 version。来源 ID 参与 P0 提案幂等摘要并写入提案证据。

缺失来源头仍表示原有手工 P0 操作；提供了来源头但无法验证时返回 `409 VOICE_INTERPRETATION_INVALID`。任何解析结果都不能自动确认提案。

## 5. D2 第一轮测试清单

| ID | 场景 | 预期 |
|---|---|---|
| D2-01 | 未登录解析 | 401，不解析 |
| D2-02 | 缺少或错误 CSRF | 403，不解析 |
| D2-03 | 非 ADMIN | 403，不解析 |
| D2-04 | 三个 requestId 不一致 | 400 |
| D2-05 | 未知字段、空白、超 200 字、非法数组 | 400 |
| D2-06 | START/PAUSE/RESUME/STOP | 四类均返回匹配候选 |
| D2-07 | “不要停止任务” | `NOT_ACTIONABLE/NEGATED_ACTION` |
| D2-08 | “暂停然后继续” | `NEEDS_CLARIFICATION/AMBIGUOUS_ACTION` |
| D2-09 | 无支持动作 | `NEEDS_CLARIFICATION/NO_SUPPORTED_ACTION` |
| D2-10 | 攻击、围捕、撤退等 | `UNSUPPORTED/UNSUPPORTED_CAPABILITY` |
| D2-11 | 指定 UAV/USV 或单艇/单机 | `UNSUPPORTED/UNSUPPORTED_TARGETING` |
| D2-12 | 运行代次或 contextVersion 变化 | 409 `VOICE_CONTEXT_CHANGED` |
| D2-13 | 同键同内容重放 | 原结果一致，不重复解析 |
| D2-14 | 同键不同内容 | 409 `IDEMPOTENCY_CONFLICT` |
| D2-15 | 候选来源属于其他用户、过期或动作不同 | 409 `VOICE_INTERPRETATION_INVALID` |
| D2-16 | 同一提案幂等键替换来源 ID | 409 `IDEMPOTENCY_CONFLICT` |
| D2-17 | 候选创建提案 | 仅创建待确认提案，不产生 execution |
| D2-18 | 用户确认后执行 | 继续由 P0 权限、状态和场景门禁决定 |

## 6. 前端联调配置

右侧“语音控制”面板继续作为唯一入口，不新增页面：

```text
VITE_VOICE_ASR_ONLY=false
VITE_VOICE_P1_PREPARATION=true
VITE_VOICE_P1_MOCK=false
VITE_VOICE_P1_BACKEND=true
```

验证顺序：录音或文字 → 可编辑文字 → 解析 → 展示候选/拒绝原因 → 点击生成待确认提案 → 人工确认。前端不得在解析成功后自动创建或确认提案；退出、换账号或运行代次变化必须清除候选。

## 7. 完成判定与后续模型接入

D2 第一轮完成需要 D2-01 至 D2-18 全部有真实 HTTP、数据库或页面证据，并回归 D1 ASR 与 P0。当前代码级测试只覆盖接口、规则分类、幂等和来源校验；真实浏览器链路尚待运行服务后验收。

若下一轮接入本地 LLM，需要另行冻结模型、运行方式和资源上限。LLM 只能替换解析器内部实现，输出仍需经过四状态 Schema、动作白名单、上下文校验和 P0 人工确认。
